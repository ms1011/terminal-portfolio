# 서비스 개요

## 서비스 목적

YAPP IT 커뮤니티 지원서에 첨부할 **"보면 바로 이해되는 백엔드 개발자 포트폴리오 사이트"**.
정적인 경력 나열이 아니라, **사이트 자체가 곧 개발자의 기술 데모**가 되는 경험을 제공한다.
- 방문 순간 터미널이 살아 움직이며(SSE 타이핑) 개발자의 서사를 전달한다.
- 지금 이 순간 같은 사이트를 보고 있는 다른 지원자/심사위원의 존재(WebSocket)를 실시간으로 드러내며, "이 사이트는 진짜 서버가 돌고 있다"는 사실을 즉각 증명한다.
- 결과적으로 "Spring Boot를 다룬다"를 텍스트가 아닌 **살아있는 행동**으로 보여준다.

## 대상 사용자

1. **YAPP 운영진/서류 심사자 (1순위)** — 짧은 시간 안에 지원자의 기술적 깊이와 열정을 판단해야 하는 사람.
2. **YAPP 동료 지원자/커뮤니티 멤버 (2순위)** — 협업 가능성과 기술 문화 적합도를 가늠하는 잠재적 동료.
3. **지원자 본인 (3순위)** — 향후 다른 채용/협업 상황에서 재사용 가능한 개인 브랜딩 자산.

## 핵심 가치 (3가지 이내)

1. **"보여주지 말고 증명하라"** — 백엔드 역량을 글로 설명하지 않고, 사이트의 동작(SSE/WebSocket)으로 직접 시연한다.
2. **"현재형 포트폴리오"** — 지금 이 순간 서버가 돌고 있고, 다른 방문자가 함께 있다는 것을 느끼게 한다. 박제된 이력서가 아니라 살아있는 시스템.
3. **"감정이 담긴 기술"** — 터미널 CRT 테마와 YAPP 지원 메시지로, 기술적 완성도와 커뮤니티를 향한 애정을 동시에 전달한다.

# 기능 목록

## Must Have

- **M1. 터미널 인트로 타이핑 연출** — 사이트 접속 시 터미널 화면에 개발자 소개 텍스트가 SSE로 한 글자/한 줄씩 타이핑되듯 스트리밍되어 나타나는 것을 볼 수 있다.
- **M2. 실시간 방문자 커서 표시** — 지금 같은 사이트를 보고 있는 다른 방문자의 존재와 현재 보고 있는 섹션/경로를 WebSocket을 통해 실시간으로 확인할 수 있다 (예: `visitor_3이 /projects를 보고 있습니다`).
- **M3. 프로젝트 목록 조회** — 주요 프로젝트(Zendesk Rate Limit → WebSocket 전환, Redis+ShedLock 분산 락, AI 생산성 시스템 등)의 문제-해결-결과를 읽을 수 있다.
- **M4. 기술 스택 확인** — 지원자의 백엔드 기술 스택(Java, Spring Boot, Redis, WebSocket 등)을 한눈에 파악할 수 있다.
- **M5. YAPP 지원 메시지 섹션** — 지원자가 YAPP에 지원하는 이유와 애정을 담은 메시지를 읽을 수 있다.
- **M6. 터미널 UI 테마** — CRT 모니터 느낌의 초록/흰색 monospace 터미널 화면에서 모든 콘텐츠를 일관된 톤으로 탐색할 수 있다.

## Should Have

- **S1. 명령어 기반 네비게이션** — 터미널처럼 `cd /projects`, `ls`, `cat about.md` 같은 명령어를 입력해 페이지를 이동할 수 있다 (링크 클릭과 병행).
- **S2. 방문자 닉네임 자동 할당** — 접속 시 자동으로 부여되는 `visitor_N` 닉네임을 통해 본인이 화면에 어떻게 표시되는지 확인할 수 있다.
- **S3. 타이핑 스킵 기능** — 인트로 타이핑이 진행되는 동안 아무 키나 누르면 즉시 전체 내용이 표시되어 빠르게 본문으로 넘어갈 수 있다.
- **S4. 접속 로그 히스토리** — 최근 N명의 방문자 접속 기록(타임스탬프, 닉네임)을 터미널 로그 형태로 볼 수 있다.
- **S5. 모바일 반응형 터미널** — 모바일 환경에서도 터미널 UI와 실시간 기능을 축소된 형태로 사용할 수 있다.

## Could Have

- **C1. 방문자 간 반응 남기기** — 터미널에 `wave` 같은 명령어를 입력해 현재 접속한 다른 방문자들에게 가벼운 인사를 보낼 수 있다.
- **C2. 이스터에그 명령어** — `sudo hire-me`, `whoami`, `uptime` 같은 숨은 명령어를 통해 재미 요소를 경험할 수 있다.
- **C3. 다크/라이트(앰버) CRT 테마 전환** — 초록 CRT와 앰버 CRT 테마를 토글해 볼 수 있다.
- **C4. 프로젝트별 상세 시퀀스 다이어그램** — 주요 프로젝트의 아키텍처를 ASCII 다이어그램으로 터미널에서 확인할 수 있다.
- **C5. GitHub 활동 연동 위젯** — 최근 커밋/PR 활동이 터미널에 로그 스트림처럼 표시되는 것을 볼 수 있다.

## Won't Have (이번 범위 외)

- 방문자 회원가입/로그인, 댓글 시스템, 방명록 DB 저장 (익명·휘발성 유지)
- 관리자 콘솔, 블로그 CMS
- 결제/연락 폼 서버 저장 (이메일 링크로 대체)

# 정보 구조 (사이트맵)

```
/ (루트 — 터미널 부팅 화면)
│
├── /intro              [M1] SSE 타이핑 인트로 — 자기소개 스트리밍
│
├── /live               [M2] 실시간 방문자 현황
│   └── WebSocket 연결 상태 + 현재 접속자 목록 + 각자의 현재 경로
│
├── /projects           [M3] 프로젝트 목록
│   ├── /projects/zendesk-websocket     Zendesk Rate Limit → WebSocket 전환
│   ├── /projects/redis-shedlock        Redis + ShedLock 분산 락
│   └── /projects/ai-harness            AI 생산성 시스템 (Markdown + Obsidian + Claude Code)
│
├── /stack              [M4] 기술 스택
│
├── /yapp               [M5] YAPP 지원 메시지
│
└── /contact            이메일/GitHub 링크 (정적)
```

보조 네비게이션: 터미널 상단 고정 프롬프트 `visitor_N@portfolio:~$` + 하단 라이브 상태 바(접속자 수, 서버 uptime).

# 사용자 시나리오

## 시나리오 1: YAPP 심사자의 첫 방문 (3분 컷)

1. 심사자가 지원서 링크를 통해 사이트 접속 → CRT 부팅 효과와 함께 검은 터미널 화면이 뜬다.
2. `"> Initializing JMS's portfolio..."` 한 줄씩 타이핑되며 인트로가 흘러간다. (SSE 스트리밍)
3. 화면 우측 상단에 `[LIVE] 2 visitors online — visitor_7 viewing /projects` 배지가 번쩍인다. 심사자는 "어? 지금 누가 같이 보고 있네?"라고 느낀다.
4. 심사자가 `/projects`로 이동하자 본인의 이동이 `visitor_8 → /projects`로 기록되고, 다른 심사자(visitor_7)의 커서도 실시간으로 보인다.
5. Zendesk Rate Limit 프로젝트를 열어보고 "WebSocket 전환 경험자가 본인 사이트도 WebSocket으로 만들었구나"를 즉시 연결 짓는다.
6. `/yapp`에서 지원 메시지를 읽고 다음 지원자로 넘어간다. **"기억에 남는 사이트"**로 각인됨.

## 시나리오 2: 동료 지원자의 발견

1. 같은 YAPP 지원자가 커뮤니티에서 링크를 공유받아 접속.
2. 본인 외에 `visitor_12, visitor_15`가 이미 접속 중인 것을 보고, "이 사이트 자체가 기술 데모구나"를 인식.
3. 터미널에 `ls /projects`를 실제로 입력해보며 명령어 UI를 테스트한다 (S1).
4. `/stack`에서 Spring Boot + Redis 조합을 확인, 본인의 관심사와 겹치는 부분을 발견.
5. GitHub 링크를 따라가 코드 저장소를 확인하고, 커뮤니티 슬랙에 "이분 사이트 진짜 재밌음"이라고 공유. **바이럴 요소 발생**.

## 시나리오 3: 연결 끊김/재접속 복구

1. 방문자가 `/projects`를 읽는 도중 네트워크가 잠시 끊긴다.
2. WebSocket 연결이 끊기자 화면 상단 상태 바가 `[DISCONNECTED] retrying...`으로 변경된다.
3. 수 초 후 재연결되면 `[LIVE] reconnected as visitor_8` 로그가 터미널 하단에 찍히며, 실시간 방문자 목록이 복구된다.
4. 사용자는 **장애 상황에서도 복원력 있게 설계된 시스템**임을 체감한다.
